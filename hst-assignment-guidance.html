Guidance for your assignment

The central problem of your assignment is the task of using calibration files to transform a raw CCD exposure into a science-ready image. Let us be clear from the start: this is not a trivial problem. Lots of really bright people have spent lots of years doing lots of testing to write robust data-reduction pipelines specifically for this purpose, so what we’re doing here is very much a simplified version that, nonetheless, gives us a pretty good idea of what’s going on when we leave the heavy lifting to a black box.

The formula for our approach is actually pretty simple:

stars + noise = (raw - bias - dark) / flat - sky

It may be tempting to just jump straight into this, but we first need to account for things like bad pixels and bias levels in our raw image before we can convert the data to physically meaningful values.

The calibration files

A full description of each of the files mentioned in the brief is available in the WFPC2 Pipeline Calibration manual, but we can briefly summarize them here.

MASKFILE

This is simply a mask of all the bad pixels. The data is stored as 16-bit integer values, where 0 represents good pixels, 2 represents defective pixels, and 256 represents “questionable pixels”. You should definitely make a plot of this and compare it to your raw exposure, and think about the values in the pixels to decide how (if at all) to use the mask file.

BLEVFILE

This is a file that contains the bias level values, which are DC offsets applied to ensure our values are always positive. The digital value stored for a pixel is limited by the resolution of the Analog-to-Digital Converter (ADC). The HST has a 16-bit ADC, meaning it can store 216 = 65536 discrete values; in practice only 12 bits are used, so pixel values will be in the range 0-4095. We want positive numbers because if we allow negative numbers, our values will be between -2048 and 2048 which results in quicker saturation of the pixels and a significant loss of data. The bias level file uses the overscan region of each chip (pixels that are always covered) to calculate the “padding” applied to ensure positive numbers. For the WFPC2, this overscan region is in columns 9-14 and rows 10-790. In Python nomenclature, we use data[row, column] so this is data[9:790, 8:14].

To make it more fun, the bias levels for even and odd rows are different. So BIASODD is the odd columns (9, 11, and 13) and BIASEVEN is the even columns (8, 10, and 12), BUT because Python indexing starts at 0 and not 1, the odd columns are even in Python nomenclature. To apply the bias level correction, we need to get the mean value of the odd overscan regions and subtract that from the odd columns of the image, and then get the mean value of the even overscan regions and subtract that from the even columns of the image.

BIASFILE

This is an image of the same shape as our science exposure which compensates for readout noise. We get it just by taking a short exposure with a closed shutter. We can simply subtract this from our bias level corrected image.

DARKFILE

This is a closed-shutter image with same exposure time as our science image, and it accounts for thermal noise. Like the bias we need to subtract this from our bias corrected image after multiplying it by our exposure time.

FLATFILE

This is an image taken with a uniform exposure that accounts for pixel sensitivity variations across our detector. The WFPC2 pipeline delivers this as an inverse sensitivity, so we multiply this by our image in the reduction workflow as opposed to dividing by it.

Some hints for the BLEVFILE

You can use slicing in Python to get odd or even columns and rows from the full data, or you could even use modulo division to check for odd or even columns/rows. A nice way to “unpack” rows and columns of a numpy array is:

for y, x in np.ndindex(data.shape):
  value = data[y, x]

Alternatively you can get the shape explicitly and use a range iteration:

nrows, ncols = data.shape 

for col in range(ncols):
  column_data = data[:, col]

It’s important to note that this file stores the overscan information for each chip in different extensions, so it is not all available in the same array! You will need to account for this in your code.

An example for parsing the BLEVFILE might be something like,

def parse_blev_file(filename, chip=0):
  with fits.open(filename) as hdul:
    data = hdul[chip].data

    # some code to parse odd and even columns here 
    odd_vals = your_odd_routine
    even_vals = your_even_routine

    return np.mean(odd_vals), np.mean(even_vals)

Putting it all together

Remember that you want this to be extensible so you aren’t repeating yourself or making unnecessary work for yourself in your code. A good way to do this is to have each process handled by a different function, and use a primary function to call all the individual tasks. You could give these tasks descriptive function names, e.g. apply_biascorr() or do_flatcorr(). A possible workflow could look like,
