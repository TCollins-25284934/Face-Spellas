Part 1: HST Calibration Routine

In our HST practicals we looked at raw data, but we primarily worked with science-ready images. But how do we get science-ready images? When we get a raw exposure from the Hubble archive, we need to do some processing: for this we can choose to download the calibration files in addition to the raw files. The different filenames are often stored in the FITS header, and for our purposes we’re interested in the following:

Keyword Description
MASKFILE Name of the input DQF of known bad pixels
ATODFILE Name of the A-to-D conversion file
BLEVFILE Engineering file with extended register data
BIASFILE Name of the bias frame reference file
DARKFILE Name of the dark reference file
FLATFILE Name of the flat field reference file

There are other higher-level calibrations we won’t do here, but if you’re interested you can look them up yourself. You can find more information about the definitions of these files in the HST Keyword Dictionary. The important calibration files are provided for you in the calibration/ folder. The basic workflow is:

  1. Mask invalid data with MASKFILE
  2. Correct Analog-to-Digital conversion errors with ATODFILE
  3. Remove bias level with BLEVFILE
  4. Remove bias image with BIASFILE
  5. Subtract dark with DARKFILE
  6. Flatfield correction with FLATFILE
  7. Remove shading with SHADFILE
  8. Photometry calibration with PHOTTAB

For this assignment you will not do steps 2 and 7, because the *_raw.fits file is already ADC-corrected and the SHADFILE is only required if the exposure time is very short. The photometry calibration can be done with the PHOTFLAM, PHOTZPT, and ZP_CORR keys in the FITS headers.

Remember that we cannot remove the noise from an image, so our calibrated image will be the stars + noise, which we can express as

  stars + noise = (raw - bias - dark) / flat - sky

You will need to work out what you think is a reasonable estimation of the sky contribution.

Part 2: Hunga Tonga Analysis

For this portion of the assignment you will be analyzing the Google Earth images and Sentinel-2 images. Specifically, you will use the Google Earth images to make a plot of the land area as a function of time, and the Sentinel-2 images to make a plot of the land area covered in vegetation as a function of time. There is a scale at the bottom of each image Google Earth image to assist you in determining the pixel size, but for the Sentinel-2 images you need to do a bit more work. All of the images are sampled to a 10m resolution, but the pixel sizes are in angular units rather than meters, so a conversion will be necessary. This can be most easily done from the image metadata:

with rasterio.open(file) as src:
    resolution = src.res
    bounds = src.bounds

The resolution variable gives the angular size of the pixels in the x- and y-directions (respectively), and bounds will give you the top, bottom, left, and right boundaries of the image in units of degrees, which are accessed with e.g. bounds.bottom. You can use these two pieces of information to work out the pixel area in units of \(\mathrm{m}^2\) and work out the total land area.

Compare and Contrast
